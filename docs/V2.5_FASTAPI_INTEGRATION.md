# V2.5 FastAPI integration

## Security integration update — 29 October 2026

Current Admin/Super Admin workspaces and native AI are integrated with FastAPI; early staged/UI-only statements below are historical. The security fix preserves React design and the current cookie workspace APIs, retires unused URL-token HTTP routes, and hardens Google/Microsoft OAuth. Public RLS/reporting now excludes private parent/master/data rows. See [security remediation evidence](V2.5_SECURITY_ARCHITECTURE_REVIEW.md) and [current API contract](../api-v1/docs/API_DOCUMENTATION.md).

## Approach

Extend the existing `api-v1` service and retain its `/api/v1` contracts. Integrate existing reporting endpoints first; then activate achievement/target and authenticated Admin/Super Admin APIs in the same service. The current production frontend and API branch remain unchanged.

## Stage 1: existing API integration

The V2.5 Netlify context enables `VITE_FASTAPI_ENABLED=true`. Same-origin `/api/v1/*` and `/strategic-plan/demo/api/v1/*` rewrites calls the existing public FastAPI service at `https://k12matrix-strategicplan.vercel.app`. Profile and goals share the existing bootstrap request. Indicator values, history, student groups, full initiative progress and the AI feature flag use the existing API. No database credential is placed in the frontend or proxy rules.

`VITE_FASTAPI_V25=false` keeps not-yet-activated calls on the approved existing paths: achievement/selected-year targets, the faster preview AI function, and the local-edit Admin/Super Admin prototype dataset. This explicit stage flag avoids sending a working preview to missing endpoints. It is not an automatic error fallback.

## Prepared API additions

The `api-v1` directory is restored from the existing `api-v1` branch; that folder was missing on V2.5 and caused the API project's failed preview builds. The service adds:

- `GET /api/v1/achievement?preview=true`: existing achievement SQL contract.
- `GET /api/v1/indicators/{id}/target?school_year=...&preview=true`: exact-year target, null when missing.
- `GET /api/v1/indicator-labels`: safe public indicator labels.
- `GET /api/v1/preview/dataset`: public canonical fields for the prototype, excluding Admin account records and credentials.

The preview service defaults `DATA_WRITES_ENABLED=false`. Legacy Super Admin mutations return 503 before calling PostgreSQL. An email alone is no longer accepted as SSO identity validation in this new preview code; the verified OAuth flow remains the intended path. Expensive diagnostic parity endpoints are disabled unless explicitly enabled. The API function region is Tokyo, matching the database region.

## Hosting prerequisite

The existing DATABASE_URL was initially Production-only. After automatic approval review required explicit authorization for the secret-scope expansion, the user approved database reading on 28 October 2026. The existing connection is now available to Preview as well; its value was not retrieved, printed or changed. No alternate credential was extracted. New preview data-write endpoints remain disabled.

A narrowly scoped SQL permission migration grants the existing `strategicuser_readonly` role SELECT on the already-public demo target table and EXECUTE on its achievement function, with a matching role-specific SELECT policy. Permission introspection confirms the new read permissions and no UPDATE permission on Indicator_Data. No district/target values were changed. A live query under this role cannot be run through the SQL connector because the connector may not SET ROLE to it; verify via the preview runtime after its connection is configured.

## Stage 2: complete Admin and Super Admin integration

Once the preview read endpoints pass hosted verification:

1. Verify new achievement endpoints against 4/7 (57.1%) and all selected-year targets; activate the V2.5 API stage flag only after parity checks pass.
2. Provide authenticated stakeholder lookup and replace the display-only review-user selector with real session-based identity.
3. Implement district-scoped assignments, master CRUD, nested initiative creation, reporting-row updates, CSV validation/import, logo updates and guarded goal deletion. Use stable database row IDs and server-side authorization on every read/write.
4. Persist edits in isolated preview storage, rather than production district records. Public preview reads must reflect those same isolated edits.
5. Move AI orchestration/provider calls and access logging into FastAPI, preserving existing grounding, answer formatting and audit behaviour. The current AI proxy still calls the existing Edge Function and is not a completed AI migration.
6. Test Admin scope, Super Admin roles, inactive users, expired sessions, cross-district requests, imports, rollback of failed batches and public dashboard parity. Production release remains a separate approval.

## Combined Vercel public preview

The preview/ Vercel build reuses api-v1/app/main.py, copied into its build root. A preview-only deployment override builds React with VITE_FASTAPI_ENABLED=true, VITE_FASTAPI_REPORTING=true, VITE_ACHIEVEMENT_PREVIEW=true and VITE_V25_UI_PREVIEW=true. VITE_FASTAPI_V25 remains false, preserving the Admin prototype scope. Achievement and selected-year targets now use the same-origin FastAPI alongside the existing public reporting calls. Both root and branded API paths are supported. No deployment-protection bypass secret or production setting is needed.

The deployment overrides the API project's root/build settings for this preview only. Existing production deployments and Git production branches remain unchanged. Python requirements reuse the existing service dependencies.

Hosted integration and loading-time findings are recorded in V2.5_PUBLIC_PREVIEW_QA.md. The combined deployment is READY; achievement and selected-year target behavior have been verified in the browser.

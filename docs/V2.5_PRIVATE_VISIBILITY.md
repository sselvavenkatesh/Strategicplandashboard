# Private master visibility

Super Admin can set Private to Yes or No on Goal Master cards, Indicator Master and Initiative Master tables, and new master dialogs. The existing Role column stores Admin for Yes and All for No. No column or table was added. Existing values are preserved unless explicitly changed.

A private goal hides its children from public FastAPI reads, even if the child itself is public. Private indicators and initiatives are excluded from their public master lists, direct reporting/history/group/target/progress/label endpoints, and preview datasets. Existing achievement SQL already respects both goal and indicator Role. Preview AI context now filters reporting rows against public goals and public masters. Public access remains independent of stakeholder assignments. Authenticated workspaces retain their existing assignment restrictions, including access to assigned private resources. Only Super Admin may change visibility.

The shared database migration changes only the existing authenticated Super Admin save function. It validates Role values, updates only supplied master visibility fields, preserves reporting data and assignments, and retains existing grants. No real resources were made private during implementation. SQL tests perform private save/reload/reversal and public-query checks in transactions that roll back all changes. Existing Super Admin and Admin save regressions also passed, with 28 focused Python API tests and 36 Node tests passing. React production build passed.

Admin and Super Admin workspaces use independent theme preferences with light as the initial default. Their theme containers do not change the public dashboard theme. Version V2.5 and Powered by K12Matrix are visible in a fixed footer on sign-in and workspace pages.

Release scope: V2.5 branch and combined Vercel preview, plus the existing district-ai-preview Edge Function (JWT verification retained). Netlify production and the district-ai production Edge Function are not redeployed. The production AI service must receive the same public-context filtering when V2.5 is released; the current production service is outside this preview deployment. Changing Role on the shared database may also affect the production public views that already honor it.

Browser layout verification was unavailable during implementation. Review the footer, theme toggle, Private controls and public visibility in the preview before release.
